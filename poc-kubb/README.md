# Kubb: OpenAPI to typed code

[Kubb](https://kubb.dev) reads an OpenAPI spec (2.0, 3.0, 3.1) and generates code from it. This POC uses a tiny Petstore spec (one endpoint, one schema) and three plugins: TypeScript types, a typed client, and Zod schemas.

Requires **Node 22.22+** (Kubb 5). Run `nvm use 22` first.

## Run it

```bash
npm install
npm run generate     # kubb generate -> src/gen (9 files)
npm run typecheck    # tsc over src/index.ts and the generated code
npm run demo:reset   # back to the "before" state (no src/gen, base spec)
```

## Files

| File | What it is |
|---|---|
| `petStore.yaml` | The OpenAPI spec (source of truth) |
| `petStore.base.yaml` | Pristine copy, used by `demo:reset` |
| `kubb.config.ts` | Input, output folder, and the three plugins |
| `src/index.ts` | Consumer code that uses the generated client and types |
| `src/gen/` | Generated by Kubb, git-ignored. Never edit by hand |

## Code walkthrough (live demo, about 2:45)

Before starting: `npm run demo:reset`, `nvm use 22`, zoom VS Code in, open `petStore.yaml`, `kubb.config.ts` and `src/index.ts`.

1. **The spec** (`petStore.yaml`, 20s). One operation, `getPetById`, with an integer `petId` path param. It returns a `Pet` with required `id` and `name`, plus a 404.
2. **The config** (`kubb.config.ts`, 20s). `input` is the spec. `output.clean: true` wipes `src/gen` on each run. Three plugins: `pluginTs`, `pluginAxios`, `pluginZod`, each with its own output folder.
3. **The consumer** (`src/index.ts`, 15s). Red squiggles everywhere, because `src/gen` does not exist yet.
4. **Generate** (terminal, 30s). `npm run generate`. About 200 ms, 9 files. The squiggles disappear and `src/gen` shows up in the explorer.
5. **Read the output** (25s):
   - `models/Pet.ts`: the type. Point at the header, "Generated by Kubb, do not edit manually".
   - `models/GetPetById.ts`: path params and a union of responses (`200`, `404`).
   - `clients/getPetById.ts`: the typed client. Note `.unwrap()` in `index.ts`.
   - `zod/petSchema.ts`: the runtime validator for the same schema.
6. **Change the spec** (25s). In `index.ts`, replace `pet.name` with `pet.tag`: red squiggle, the spec has no `tag`. In `petStore.yaml`, add under `name`:
   ```yaml
   tag:
     type: string
   ```
   Run `npm run generate`. The squiggle is gone and `Pet.ts` now has `tag?: string`.
7. **Optional** (10s). `npm run typecheck` for a clean compile.

## What I verified

- `npm run generate` creates 9 files in about 200 ms.
- `pet.name` compiles. A typo (`pet.nme`) fails with TS2551.
- `pet.tag` fails before the spec change (TS2339) and compiles after regenerating.

## Gotchas

- **Node 22.22+** is required. Node 18/20 will not work.
- `int64` is generated as `bigint` (`id: bigint`), so `petId: 1n` in the call. Check how your serializers and JSON handling treat `bigint` before adopting it.
- `output.clean: true` deletes the contents of `src/gen`. Keep only generated files there.
- `src/index.ts` is a type-level demo. It is not meant to hit the real Petstore API.

## Alternatives

orval (closest in breadth), HeyAPI (runtime validation of requests and responses), openapi-typescript (types only, fastest for that case). Kubb also generates Cypress tests, Redoc docs and an MCP server, which the others in that comparison do not (source: kubb.dev comparison page).
